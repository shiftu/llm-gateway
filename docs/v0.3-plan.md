## §1. Confirmed Premises (v0.3 deltas)

Inherited from v0.1/v0.2:

- **P1.** v0.1+v0.2 multi-tenant baseline is stable; never break stability.
- **P2.** AI-native MCP-only control plane. No web UI. No exceptions.
- **P3.** Dual-protocol inbound (OpenAI + Anthropic).
- **P4.** Multi-tenant as default.
- **P5.** Single static Go binary + SQLite.
- **P6.** AI-native thesis — operator IS a coding agent.

New for v0.3:

- **P7.** **Cognitive ≠ surprising.** Every cognitive routing decision is explainable via `explain_route(request_id)`. Agents must always be able to ask "why."
- **P8.** **Reasoning is first-class semantics, not provider-specific syntax.** One IR; per-protocol emitters at the boundary.
- **P9.** **Resources + Prompts are now part of the moat.** MCP tools were the v0.1 control surface; v0.3 adds the agent-data surface.

### Competitive positioning recap

- LiteLLM has fallback policies but no cognitive scoring, no reasoning IR, no MCP resources.
- OpenRouter has cost/latency routing but no MCP, no Chinese-provider depth.
- Helicone has tracing/logs but no routing.
- **llm-gateway's wedge in v0.3:** cognitive routing + unified reasoning IR + MCP-native runtime + Chinese-provider depth — **all four together, in one ~12MB binary.**

### Storage schema additions

```sql
-- v0.2 → v0.3 migration (idempotent via user_version)

-- 1) Routing weights (per-team override of default cost/latency/quality/health weights)
CREATE TABLE routing_weights (
  team_id     TEXT PRIMARY KEY REFERENCES teams(id) ON DELETE CASCADE,
  cost        REAL NOT NULL DEFAULT 0.4,
  latency     REAL NOT NULL DEFAULT 0.3,
  quality     REAL NOT NULL DEFAULT 0.2,
  health      REAL NOT NULL DEFAULT 0.1,
  updated_at  INTEGER NOT NULL
);

-- 2) Fallback policies
CREATE TABLE fallback_policies (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  team_id         TEXT REFERENCES teams(id) ON DELETE CASCADE,
  trigger         TEXT NOT NULL,
  threshold       REAL,
  action          TEXT NOT NULL DEFAULT 'next_best',
  max_chain_depth INTEGER NOT NULL DEFAULT 3,
  is_active       INTEGER NOT NULL DEFAULT 1,
  created_at      INTEGER NOT NULL,
  CHECK (trigger IN ('quota_exhausted','http_5xx','http_429','latency_exceeded')),
  CHECK (action IN ('next_best','specific_provider'))
);

-- 3) Per-team dollar budgets
CREATE TABLE budgets (
  team_id            TEXT NOT NULL REFERENCES teams(id) ON DELETE CASCADE,
  period             TEXT NOT NULL,
  usd_limit          REAL NOT NULL,
  soft_threshold_pct INTEGER NOT NULL DEFAULT 80,
  hard_cap_action    TEXT NOT NULL DEFAULT 'block',
  updated_at         INTEGER NOT NULL,
  PRIMARY KEY (team_id, period),
  CHECK (period IN ('day','month')),
  CHECK (hard_cap_action IN ('warn','block'))
);

-- 4) Master key registry (for rotation)
CREATE TABLE master_keys (
  id           TEXT PRIMARY KEY,
  key_enc_b64  TEXT NOT NULL,         -- encrypted with KEK
  label        TEXT,
  created_at   INTEGER NOT NULL,
  retired_at   INTEGER                -- null = active
);

-- 5) Provider capabilities
CREATE TABLE provider_capabilities (
  provider_name TEXT NOT NULL REFERENCES providers(name) ON DELETE CASCADE,
  capability    TEXT NOT NULL,
  value         TEXT NOT NULL,         -- "true" | "false" | numeric-as-text
  updated_at    INTEGER NOT NULL,
  PRIMARY KEY (provider_name, capability)
);

-- 6) Aliases gain a routing mode
ALTER TABLE model_aliases ADD COLUMN mode TEXT NOT NULL DEFAULT 'static'
  CHECK (mode IN ('static','cognitive'));

-- 7) Request logs gain a route trace
ALTER TABLE request_logs ADD COLUMN route_trace TEXT;  -- nullable JSON
```
